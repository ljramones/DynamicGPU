# DynamisGPU 1.11.1

Released 2026-11-25.

Version 1.11.1 adds batched decode to 1.11.0's paged KV cache. One dispatch decodes many sequences of different
lengths through their page tables, as a server's continuous batching needs. 1.11.0 took one sequence per dispatch.

Like 1.11.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **`AttentionF16.encodeBatch`:** a decode step for a batch of `PagedKvCache` sequences.
  - **Shape:** `AttentionF16.DecodeBatch(heads, kvHeads, queries, headDim, scale, causal)`, or `DecodeBatch.of` for
    one causal query per sequence. Q and O are `[batch][heads][queries][headDim]`.
  - **What each sequence attends:** all of its tokens. Sequences may differ in length and may share pages.
  - **Rows:** at most 8 per KV head (`heads / kvHeads * queries`), the decode kernel's limit.
  - **How:** group x of the decode kernel is the sequence. Its tokens and the offset of its pages come from a header
    in the batch's page table.
  - **Accuracy:** each sequence's rows are within the fused bound (`fusedContract`) of its own keys and values.
- **Chunked key ranges:** the decode kernel walks a key range in chunks of the scores it keeps, and rescales its
  running max, sum and accumulators between chunks.
  - **Batched decode** therefore picks ranges for parallelism alone. A large batch gets one range per sequence and
    needs no combine.
  - **Unbatched decode** keeps 1.11.0's ranges, one chunk each, with the same arithmetic.
- **A shared batch table:** `PagedKvCache` keeps a batch's table, immutable, until a sequence's tokens or pages
  change, so the layers of a step share one table. Recorded commands keep the table they were recorded with.

## Measured

On an M4 Max: 32 heads, 8 KV heads, head dimension 128, FP16 O, each sequence on its own pages.

| Batch x keys | Batched: GPU / host | One encode per sequence: GPU / host |
|---|---|---|
| 8 x 4096 | 422 us (318 GB/s) / 12 us | 580 / 70 us |
| 32 x 1024 | 414 us (324 GB/s) / 7 us | 1,251 / 223 us |
| 32 x 4096 | 1,549 us (347 GB/s) / 10 us | 2,323 / 209 us |
| 64 x 512 | 373 us (360 GB/s) / 8 us | 1,420 / 337 us |

Single-sequence decode is unchanged within noise: 9.7, 46 and 336 us at 512, 4096 and 32768 keys.

## Fixed along the way

- **The fixed-tree decode kernel had stopped running on hardware.** Devices without subgroup arithmetic use it. All
  three test devices have subgroups, so since 1.11.0 its numbers were checked nowhere. A test switch now forces it
  through the single and batched decode checks on every backend.

## Behaviour changes to check

- **The attention kernels' parameter block gains a `batch` field**, which is 0 outside batched decode. Code that only
  uses `AttentionF16` is unaffected.

## Known limits

- **Batched prefill:** batched decode takes at most 8 rows per KV head, so prompt chunks of several sequences can't
  share a dispatch.

## Install and consume

All public artifacts use version `1.11.1` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.11.1 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.11.1-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.11.1-maven.zip
unzip dynamisgpu-1.11.1-maven.zip
sh dynamisgpu-1.11.1/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.11.0 artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.
