# DynamisGPU 1.9.0

Released 2026-11-24.

Version 1.9.0 completes milestone 1.9 of the [roadmap](../roadmap.md): block-quantized weights. Decode is limited by
memory bandwidth, and 4-bit weights with block 32 take 0.28 of FP16's bytes. On an M4 Max, a decode step with Q4
weights runs 2.9 to 4.0 times faster than with FP16 weights. Every result is bit for bit a CPU reference on native
Metal, MoltenVK and lavapipe.

Like 1.8.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **`QuantizedMatrix`:** three block formats, compatible in meaning with the common Q8_0, Q4_0 and Q4_1 schemes.
  - **Formats:** `Q8` (`q d`, codes -127 to 127), `Q4` (`q d`, -8 to 7) and `Q4M` (`q d + m`, 0 to 15).
  - **Blocks:** 32 or 64 elements along each row, with FP16 parameters.
  - **CPU side:** the encoder (`quantize`), the decoder (`dequantize`, `value`), the packed layout and the error
    bound.
  - **The same bits everywhere:** scales come from one correctly rounded multiply, and codes are corrected against
    exact midpoints, so no device's division or conversion changes them.
- **`Quantize`:** the GPU quantizer and dequantizer (`pack`, `unpack`), bit for bit the CPU's on every device.
  - **Refusals:** a non-finite value, or a scale beyond FP16, fails the submission with `KERNEL_ERROR`.
- **`QuantizedGemm`:** `C = epilogue(alpha A W^T + beta C)` with FP16 or BF16 activations and packed weights,
  dequantized inside the kernel.
  - **Algorithms:** `SKINNY` for decode (`m <= 16`) and `TILED` for prefill.
  - **Specialization:** each pipeline is specialized per format, block size and (decode) rows tier.
  - **Exactness:** activation-code products are exact in FP32, and every order is fixed. The result is therefore bit
    for bit `QuantizedGemm.reference` everywhere, lavapipe included, although it doesn't fuse `fma`.
  - **Epilogues:** `GemmF16`'s apply.
- **Measured decode** (M4 Max, m = 1, weights rotated past the system cache):

  | n x k | FP16 weights | Q8 | Q4 | Q4M |
  |---|---|---|---|---|
  | 4096 x 4096 | 83 us | 43 us | 29 us | 35 us |
  | 11008 x 4096 | 250 us | 105 us | 62 us | 68 us |
  | 4096 x 11008 | 228 us | 110 us | 70 us | 73 us |

  - **More rows:** at m = 4 the quantized product runs 1.3 to 2.2 times faster than FP16, and at m = 16 about the
    same.
  - **Prefill:** `TILED` runs about 4.6 TFLOP/s at m = 512.
- **Benchmark:** `-Dquant.decode=true` runs the decode comparison.

## Behaviour changes to check

- None to existing APIs.
- **The GEMM parameter block:** the quantized kernels add a `qparams` field. The other kernels' blocks are unchanged.

## Not done

- **A quantized form of the matrix kernel:** prefill with quantized weights runs `TILED`.
- **The CPU formats are in DynamisGPU,** not Vectrix `nn.Formats`. Vectrix can adopt them when the capabilities flow
  into it.
- **No FP16 tile packing:** the matrix kernel already reads row-major weights at full rate.

## Install and consume

All public artifacts use version `1.9.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.9.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.9.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.9.0-maven.zip
unzip dynamisgpu-1.9.0-maven.zip
sh dynamisgpu-1.9.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.8.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (463 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives (GEMM, quantized, softmax, attention, kit) |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 45 | 33 |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | 48 | 33 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 48 | 33 |

- **Quantized weights:** the GPU's packed bytes, dequantized values and quantized products match the CPU's bit for
  bit on every target. This covers every format, block size, activation and output type, and both algorithms, with
  epilogues and batches.
- **Cross-backend harness:** native Metal against MoltenVK passes.
- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6, unchanged) targets macOS 13.0 arm64.
The stricter runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
