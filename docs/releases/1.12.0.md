# DynamisGPU 1.12.0

Released 2026-11-25.

Version 1.12.0 completes milestone 1.12 of the [roadmap](../roadmap.md): training kernels. It adds backward passes for
the activations, softmax, norms and attention, a cross-entropy loss, and AdamW and SGD. Every gradient is summed in a
fixed order, so a device's results do not depend on scheduling.

Like 1.11.1, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **Activation backward passes:** `Elementwise.Binary.RELU_BACKWARD` (exact), `SILU_BACKWARD` and `GELU_BACKWARD`.
  - **Bounds:** absolute, carried through each step from exp's error, because the derivatives cross zero.
  - **SwiGLU:** its gradients compose from these.
- **`Softmax.backward`:** `dx = y (dy - sum dy y)`, with the forward pass's mask, batches and layouts. y is FP32 or
  FP16, and the sum uses the forward pass's fixed tree.
- **`Norms.backward`:** RMSNorm's and LayerNorm's dv from v, w and dy.
  - **Residual stream:** `accumulate` adds dv to the residual stream's gradient.
  - **Weight and bias gradients:** added from per-block partials in order.
- **`CrossEntropy`:** each row's loss against a target on the GPU, and its gradient.
  - **Options:** the gradient can be written in place, and an ignore index gives a row of zeros.
  - **Errors:** a target past the vocabulary fails the submission.
  - **Size:** multi-group log-sum-exp, checked at a vocabulary of 128256.
- **`Optimizer`:** AdamW and SGD (momentum, Nesterov, weight decay) over FP32 parameters.
  - **Inputs:** FP32 or FP16 gradients, and an optional gradient scale read on the GPU, for clipping or unscaling
    without a host sync.
  - **Output:** an optional FP16 copy of the updated weights.
  - **Exactness:** bit for bit the Java references on native Metal, MoltenVK and lavapipe.
- **Attention training:**
  - **Forward:** `AttentionF16.encode(..., lse, shape)` also writes each row's log-sum-exp.
  - **Backward:** `AttentionF16.backward` gives dQ, dK and dV.
    - **Kernels:** a pre-pass for `rowsum(dO O)`, one kernel per key block for dK and dV, and one per query block for
      dQ.
    - **P:** recomputed in FP32.
    - **Coverage:** grouped-query attention, the causal mask and caches longer than the keys.
- **Gradient checks:** `GradientReferenceTest` checks every backward reference against finite differences of its
  forward pass in double: softmax, both norms, cross-entropy, the activation derivatives and the attention formulas.
- **Transposed-A GEMM**, from the roadmap's list, has been in `GemmF16` since 1.8.0 (`Shape.ofTransposedA`).

## Measured

On an M4 Max, the attention backward pass at 32 heads, head dimension 128, causal, FP16 O:

| Sequence | Training forward | Backward |
|---|---|---|
| 512 | 0.41 ms | 3.5 ms |
| 1024 | 1.38 ms | 13.3 ms |
| 2048 | 5.15 ms | 51.5 ms |

The backward pass is portable scalar code, at about 10 times the forward pass's time.

## Behaviour changes to check

- **`Elementwise.Binary` gains three values:** a switch over it needs the new cases.
- **The fused attention's parameter block gains `writeLse`,** and the flash kernels and the combine gain an `lse`
  binding. Code that only uses `AttentionF16` is unaffected.

## Known limits

- **No float atomics.** The roadmap planned gradient accumulation with float atomics. This release uses fixed orders
  instead: per-block partials, and a separate dQ kernel in the attention backward. So the gradients do not depend on
  scheduling, at the cost of the dQ kernel's recompute, about half of the attention backward's time.
- **No Metal matrix-path attention backward yet.** The forward pass's matrix path made it about 2 times faster; a
  backward one is the next step.

## Install and consume

All public artifacts use version `1.12.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.12.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.12.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.12.0-maven.zip
unzip dynamisgpu-1.12.0-maven.zip
sh dynamisgpu-1.12.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.11.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (531 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 45 | 56 |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | 48 | 56 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 48 | 56 |

- **Cross-backend harness:** native Metal against MoltenVK passes.
- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6, unchanged) targets macOS 13.0 arm64.
The stricter runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
