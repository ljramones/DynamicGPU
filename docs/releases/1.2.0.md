# DynamisGPU 1.2.0

Released 2026-11-24.

Version 1.2.0 adds four things:
- **Data layouts:** it takes over the GPU data-layout code from Vectrix.
- **Capability tiers:** devices report half precision, small and wide integers, doubles, subgroups and atomics.
- **The first throughput primitive:** `GemmF16`, a half-precision matrix multiply.
- **Shader tooling:** a shared Slang shader toolchain and kernel error buffers.

The hardware suites now run in CI. Like 1.1.0, it is distributed through GitHub and local Maven installation, not
Maven Central.

## New

- **GPU data layouts, moved from Vectrix** ([GPU data layouts](../gpu-data-layouts.md)):
  - **`ShaderLayout`** (`dynamis-gpu-api`, `org.dynamisengine.gpu.api.layout`): std140, std430 and scalar
    block layouts with GLSL emission, checked against glslang's layouts (the golden and its script came with it).
  - **`dynamis-gpu-vectrix`:** a new module, the only one that depends on Vectrix (3.2.1). It holds
    `GpuTransformLayout`, `GpuTransformWriteKernels` and `InstanceSubmissionPipeline`
    (`org.dynamisengine.gpu.vectrix`).
    - **Unchanged:** behaviour and tests are as in Vectrix.
    - **Renamed property:** `InstanceSubmissionPipeline`'s system property is now
      `dynamisgpu.instanceSubmission.forceMatrix`. The old `vectrix.runtime.instanceSubmission.forceMatrix` still
      works.
  - **`VertexFormat`:** gains the formats Vectrix's vertex layout had and DynamisGPU lacked: `FLOAT16X4`,
    `UNORM16X2`, `UNORM16X4`, `SNORM16X2`, `UINT32X1` to `UINT32X4`, `UINT8X2`, `INT8X2`, `UNORM8X2` and
    `SNORM8X2`.
- **Capability tiers:** devices report the optional data types (`FP16`, `INT16`, `INT8`, `INT64`, `FP64`) and shader
  features they support: subgroup operations (`SUBGROUP_BASIC`, `_VOTE`, `_ARITHMETIC`, `_BALLOT`, `_SHUFFLE`),
  `ATOMIC_FLOAT32_ADD` and `ATOMIC_INT64`.
  - **Where to find it:** [compute-runtime.md](../compute-runtime.md) has the table, with what each target reports.
  - **Enabling:** each backend enables what it reports.
  - **Subgroup sizes:** `GpuCapabilities` gains `minSubgroupSize()` and `maxSubgroupSize()`. The 1.1 constructor
    remains, with no subgroups.
  - **Refusing modules:** on Vulkan, a SPIR-V module that needs a feature the device lacks is refused with
    `UNSUPPORTED`.
  - **Conformance:** `CapabilityTierConformance` checks every tier exactly on native Metal, MoltenVK and lavapipe.
- **Throughput primitives:** the new `dynamis-gpu-primitives` module ([primitives.md](../primitives.md)).
  - **`GemmF16`:** a half-precision matrix multiply, FP16 inputs with an FP32 accumulator and output.
  - **Speed:** 5.6 TFLOP/s at 4096³ on an M4 Max with native Metal, and 5.4 with MoltenVK.
  - **Accuracy:** it is accuracy-bounded by contract.
  - **Reproducibility:** this version gives the same bits on native Metal, MoltenVK and lavapipe as its CPU
    reference.
- **Kernel error buffers:** `KernelErrors`, `ComputeException.Code.KERNEL_ERROR`, and `GpuCommandEncoder.resetErrors`
  and `checkErrors`. Kernels report data-dependent errors without poisoning the queue; shader helpers come in GLSL,
  Metal and Slang.
- **Shader toolchain:** the `dynamis-gpu-shaders` module (`ShaderBuild`) compiles Slang to SPIR-V and Metal with the
  rounding rules in [compute-runtime.md](../compute-runtime.md) and writes a manifest. `KernelLibrary`
  (`dynamis-gpu-api`) loads that manifest at runtime.
- **CI:** the Metal and MoltenVK suites run on a self-hosted Apple GPU runner, for pushes.

## Behaviour changes to check

- **Vulkan instances and devices:**
  - **Instance:** the instance asks for the loader's API version, up to 1.3 (it was 1.1).
  - **Device:** the device enables the reported tiers' features, plus `VK_EXT_shader_atomic_float` where present.
- **Unsupported SPIR-V:** a SPIR-V module that declares a capability the device did not enable is now refused at
  pipeline creation. Previously it reached the driver, which is undefined behaviour.
- **Metal bridge ABI 2:** it adds `dg_device_features`. A bridge built from 1.1 sources is refused with an ABI mismatch.
- **ShaderBuild targets:** kernels lists take an optional fourth field. `KernelLibrary` bundles a backend's executable
  only when the manifest records it.

## Deprecated

- **`VertexFormat.UINT8X4_NORM`:** it is the same format as `UNORM8X4`; use that.

## Install and consume

All public artifacts use version `1.2.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives` (new): throughput kernels
- `dynamis-gpu-vectrix` (new): GPU data written from Vectrix types; add it only where code needs that.
  - **Its Vectrix dependency:** it depends on `org.dynamisengine:vectrix:3.2.1`, which is distributed through the
    [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.2.1), not Maven Central.
- `dynamis-gpu-shaders`: the build-time Slang shader tool
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.2.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.2.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.2.0-maven.zip
unzip dynamisgpu-1.2.0-maven.zip
sh dynamisgpu-1.2.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.1.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (311 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target:

  | Target | Driver | Compute conformance (incl. tiers) | GemmF16 |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 30 | 4 (benchmark opt-in) |
  | MoltenVK | 1.4.1 on the same machine | 31 | 4 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 31 | 4 |

- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 2) targets macOS 13.0 arm64. The stricter
runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
