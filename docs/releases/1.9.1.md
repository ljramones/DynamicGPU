# DynamisGPU 1.9.1

Released 2026-11-24.

Version 1.9.1 extends 1.9.0's quantized weights to the formats real models ship in. A survey of the GGUF models on
the development machine found mostly Q4_K with Q6_K (the "Q4_K_M" mix), with Q4_0 and Q8_0 in the rest. This release
adds those K formats, block size 128, and a lossless importer for llama.cpp's blocks.

Like 1.9.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **K formats** (`QuantizedMatrix.Format.Q4K`, `Q5K`, `Q6K`): llama.cpp's Q4_K, Q5_K and Q6_K.
  - **Structure:** super-blocks of 256 with FP16 `d` (and `dmin`), and 6-bit or int8 sub-block scales.
  - **Exactness:** dequantized bit for bit as llama.cpp does.
  - **Where they work:** in `QuantizedGemm` (decode and prefill) and in `Quantize.unpack`, with every result bit for
    bit `QuantizedGemm.reference` on native Metal, MoltenVK and lavapipe.
  - **Encoding:** `QuantizedMatrix.quantize` has a simple encoder for them. llama.cpp's tools search the scales and
    are more accurate; import their output.
- **Block size 128** for Q8, Q4 and Q4M: the group size of GPTQ and AWQ models.
- **`GgufBlocks`:** GGML `Q4_0`, `Q4_1`, `Q8_0`, `Q4_K`, `Q5_K` and `Q6_K` tensor blocks to `QuantizedMatrix`
  (`fromGgml`) and back (`toGgml`).
  - **Lossless:** the codes and scales move unchanged.
  - **Checked against gguf-py** (llama.cpp's Python package), bit for bit:
    - synthetic blocks of every type, committed as a test resource;
    - opt-in (`-Dgguf.samples`), slices of three real models' Q4_0, Q4_K, Q6_K and Q8_0 tensors. These also dequantize
      and multiply bit for bit on all three backends.
  - **The oracle script:** `scripts/ggml-oracle.py` writes both sample files.
- **Measured decode** (M4 Max, m = 1, weights rotated past the system cache): Q4K runs 2.9 to 3.7 times faster than
  FP16 weights, Q5K 2.3 to 3.0, and Q6K 2.1 to 2.8. Prefill takes 3.5 to 4.1 ms at m = 512 x 4096 x 4096 for every
  format. Tables are in [primitives.md](../primitives.md).

## Improved

- **The quantized tiled kernel** stages each unit's scales in group memory with the tiles.
  - **Faster:** Q4 prefill at m = 64 went from 825 to 565 us.
  - **Smaller:** it packs two rows of A per word, staying within 16 KiB of group memory.
- **The decode benchmark** (`-Dquant.decode=true`) warms up and sizes its rounds to about 20 ms of GPU work.
  - **Repeatable:** results repeat within about 1 %.
  - **Filters:** `-Dquant.m`, `-Dquant.formats` and `-Dquant.short` narrow a run.

## Behaviour changes to check

- **`QuantizedMatrix` layout:** it gains a high-bit plane (`highOffset`, `highBytes`) before the parameters.
  - **Q8, Q4 and Q4M:** the plane is empty, so their layout is unchanged.
- **The quantized kernels' parameter block** adds `qhigh`; `qformat` and `qblock` are specialization constants.
- **`Quantize.pack`** refuses the K formats, which have no GPU encoder.

## Not included

- **Formats:** Q5_0 and Q5_1, the IQ and 2- to 3-bit formats, and FP8 weights.
- **A GGUF container reader:** the header, metadata and tensor table are left to the caller (NNJava).

## Install and consume

All public artifacts use version `1.9.1` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.9.1 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.9.1-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.9.1-maven.zip
unzip dynamisgpu-1.9.1-maven.zip
sh dynamisgpu-1.9.1/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.9.0 artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (TESTS_PORTABLE tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives (GEMM, quantized, softmax, attention, kit) |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | TESTS_METAL_COMPUTE | TESTS_METAL_PRIM |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | TESTS_MVK_COMPUTE | TESTS_MVK_PRIM |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | TESTS_LVP_COMPUTE | TESTS_LVP_PRIM |

- **Real model weights:** they import, dequantize and multiply bit for bit on every target (opt-in, not counted).
- **Cross-backend harness:** native Metal against MoltenVK passes.
- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6, unchanged) targets macOS 13.0 arm64.
The stricter runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
