# DynamisGPU 1.4.0

Released 2026-11-24.

Version 1.4.0 adds the building blocks of a transformer layer to the throughput primitives:
- **Matrix multiply:** `GemmF16` gains transposed B, batches and FP16 output.
- **`Softmax`:** row-wise, with a causal mask.
- **`AttentionF16`:** scaled dot-product attention for every head at once.

Like 1.3.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **`GemmF16` covers linear layers and attention** ([primitives.md](../primitives.md)):
  - **Transposed B** (`Shape.ofTransposedB`, `transposeB`): `C = A B^T`, with B stored `n x k`, as the weights of a
    linear layer are.
  - **Batches** (`batched`, `withBatch`): many multiplies in one dispatch, with per-matrix strides. A stride of 0
    shares one matrix across the batch.
  - **FP16 output** (`create(device, Precision.FP16)`): the FP32 result, rounded once to the nearest half.
  - **Both algorithms:** each new form runs on both algorithms.
  - **Reproducibility:** the tiled algorithm stays bit for bit with `GemmF16.reference` and `referenceF16` on native
    Metal, MoltenVK and lavapipe.
  - **Speed:** the matrix algorithm runs at 12.7 TFLOP/s at 4096³ on an M4 Max, with B either way round.
- **`Softmax`:** a row-wise softmax of FP32 scores, batched, writing FP32 or FP16.
  - **Mask:** an optional causal mask, with a KV-cache offset.
  - **Accuracy:** it reduces in a fixed order, and its result is held to a bound because `exp` is the device's own.
- **`AttentionF16`:** scaled dot-product attention for every head, from `GemmF16`, `Softmax` and `GemmF16`.
  - **Mask:** causal or none.
  - **Output:** FP16 or FP32.
  - **Accuracy:** every element of O is within the composition of the steps' bounds on native Metal, MoltenVK and
    lavapipe.
  - **Speed:** 32 heads x 2048 tokens x 128 dims, causal, takes 7.4 ms on an M4 Max.
  - **Scratch memory:** it uses scratch buffers of `heads x queries x keys` scores; a fused kernel is planned.
- **`Precision`:** the output type shared by the primitives (FP32, FP16).

## Behaviour changes to check

- **`GemmF16` kernel parameter block:** it grew from 8 to 12 fields (48 bytes).
- **`GemmF16.Shape`:** it gained `transposeB`, `batch` and the three strides. The 8-argument constructor remains.

## Install and consume

All public artifacts use version `1.4.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.4.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.4.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.4.0-maven.zip
unzip dynamisgpu-1.4.0-maven.zip
sh dynamisgpu-1.4.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.3.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (341 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target:

  | Target | Driver | Compute conformance (incl. tiers) | Primitives (GemmF16, Softmax, Attention) |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 32 | 15 (benchmarks opt-in) |
  | MoltenVK | 1.4.1 on the same machine | 33 | 15 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 33 | 15 |

- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 3) targets macOS 13.0 arm64. The stricter
runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
