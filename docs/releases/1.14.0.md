# DynamisGPU 1.14.0

Released 2026-11-25.

Version 1.14.0 adds what NNJava's GPU adapter needs to run whole tensor programs, its throughput requests G-T1 to
G-T7 (NNJava's `docs/numerical-coverage.md`): comparisons, masks and casts, reductions along any axis, gather and a
fixed-order scatter-add, gradient clipping, sigmoid and tanh, the RoPE backward pass, and padding masks in softmax.
Every new kernel accumulates in a fixed order, with no float atomics.

Like 1.13.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **`Logic`** (G-T1): comparisons of FP32 or INT32 words into uint32 masks, AND/OR/XOR/NOT, FP32 classification
  (finite, NaN, infinite), wrapping int32 arithmetic, and `select` between 32-bit words. Integer arithmetic on the
  bits: bit for bit its Java reference on every device, subnormals included.
- **`Cast`** (G-T1): FP32, FP16, BF16, INT32 and BOOL, every pair, bit for bit. FP32 to INT32 is Java's `(int)`
  cast; the narrowing float conversions round to nearest even.
- **`Reduce` along any axis** (G-T2): `axis` and `argmaxAxis` move the dimension last in the view and use the same
  fixed tree; `Op.MEAN`; `maxBackward` routes a max's gradient to the first largest element (or first NaN).
- **`Gather`** (G-T4): `gather` along any dimension by GPU-resident uint32 indices, and `scatterAdd`, its gradient and
  the embedding's backward pass. A repeated index's rows add in increasing position: bit for bit on every device.
- **`Elementwise` sigmoid and tanh** (G-T5): `SIGMOID`, `TANH`, `SIGMOID_BACKWARD` and `TANH_BACKWARD`. Worst
  measured errors 3, 2 and 5 ULP, within their contracts.
- **`GradientClip`** (G-T3): `squaredNorm`, a fixed-order sum of squares over a list of tensors into one GPU value
  (bit for bit), and `clip`, in-place scaling by `maxNorm / norm` read on the GPU.
- **`Rope.encodeBackward`** (G-T6): the inverse rotation, bit for bit, both layouts and partial rotary dimensions.
- **`Softmax` valid lengths** (G-T7): `encode` and `backward` take an optional buffer of lengths, masking matrix z's
  columns at or past `lengths[z / lengthGroup]`, with or without the causal mask.

The [primitives guide](../primitives.md#tensor-programs-1140) describes each, with its accuracy contract.

## Behaviour changes to check

- **A softmax row of -infinity scores is zeros.** A row whose unmasked scores are all -infinity (an additive mask)
  now gives zeros, not NaN, and a zero gradient. Rows with any finite score are unchanged.
- **`Reduce.Op` has a fourth value, `MEAN`.** `Scan.rows`, which takes the same enum, refuses it. A `switch` over
  `Reduce.Op` needs a case for it.
- **`Elementwise.Unary` and `Binary` have new values** at their ends; existing operations and their results are
  unchanged.
- **Activation gradients take the forward input.** `SIGMOID_BACKWARD` and `TANH_BACKWARD` take x (as `SILU_BACKWARD`
  and `GELU_BACKWARD` do), not the output y that Vectrix's CPU versions take.
- **Softmax kernels gained a binding** (the lengths, slot 2 forward and 3 backward). Code using `Softmax` is
  unaffected; code dispatching its kernels directly must bind it.

Not done in this release:
- **Masks in `AttentionF16`'s fused kernels** (the rest of G-T7); padded attention composes from `GemmF16` and
  `Softmax` with lengths.
- **GELU's erf form,** convolution and pooling (G-T8), and mixed-precision training support (G-T9).

## Install and consume

All public artifacts use version `1.14.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`: it depends on `org.dynamisengine:vectrix-ml:4.0.0`.
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix-render:4.0.0`.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

Vectrix 4.0.0 comes from the [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v4.0.0), as a
Maven repository ZIP. Install it first:

```sh
gh release download v4.0.0 --repo ljramones/vectrix \
  --pattern 'vectrix-4.0.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 vectrix-4.0.0-maven.zip
unzip vectrix-4.0.0-maven.zip
sh vectrix-4.0.0/install.sh

gh release download v1.14.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.14.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.14.0-maven.zip
unzip dynamisgpu-1.14.0-maven.zip
sh dynamisgpu-1.14.0/install.sh
```

Compare each ZIP digest against its `SHA256SUMS` before installation; download the two releases into separate
directories. Existing 1.13.x artifacts are unchanged. The external `dynamis-parent` stays at `1.0.1`. The class-path
JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (552 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 45 | 66 |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | 48 | 66 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux arm64 in a local container (x86_64 in CI) | 48 | 66 |

- **New tests:** `TensorOpsConformance` (10 tests per backend) covers every new primitive bit for bit or within its
  contract; `InferenceConformance.ropeIsBitForBit` covers the backward pass; `GradientReferenceTest` checks it against
  the forward rotation.
- **vectrix-gpu:** Vectrix's vectrix-gpu uses `dynamis-gpu-api`, which this release does not change.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6, unchanged) targets macOS 13.0 arm64.
The stricter runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
