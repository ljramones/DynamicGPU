# DynamisGPU 1.13.0

Released 2026-11-25.

Version 1.13.0 moves DynamisGPU onto Vectrix 4.0, completing the roadmap's flow into Vectrix: the block quantization
math now lives in Vectrix, and DynamisGPU keeps the GPU side. No kernel and no result changes.

Like 1.12.1, it is distributed through GitHub and local Maven installation, not Maven Central.

## Changed

- **`QuantizedMatrix`'s math is Vectrix's `BlockQuant`.**
  - **Delegated:** the encoders, the K formats' scale packing and the decoding call Vectrix 4.0's
    `org.dynamisengine.vectrix.nn.BlockQuant`, which holds the same six formats under the same names. It was ported
    from `QuantizedMatrix` and is tested bit for bit against gguf-py.
  - **Kept here:** `QuantizedMatrix` keeps the GPU layout (codes, high bits, parameters), and its public API is
    unchanged.
  - **Checked:** 1.12.1's and 1.13.0's `QuantizedMatrix` give the same packed bytes and the same decoded bits on 480
    matrices across all six formats, including all-zero blocks, exact ties and arbitrary bytes. They reject the
    same inputs.
- **`dynamis-gpu-vectrix` is on Vectrix 4.0.** It depends on `vectrix-render` (whose GPU encodings, `Half` and
  `QuatCompression`, it uses), which brings `vectrix-core`. It was on the single `vectrix` 3.3.0 jar.

## Behaviour changes to check

- **New dependency:** `dynamis-gpu-primitives` depends on `org.dynamisengine:vectrix-ml:4.0.0` (and through it
  `vectrix-core`). Its module requires `org.dynamisengine.vectrix.ml` but does not re-export it: no public method of
  the primitives takes or returns a Vectrix type.
- **Module path:** `org.dynamisengine.gpu.vectrix` requires `org.dynamisengine.vectrix` and
  `org.dynamisengine.vectrix.render` transitively.
- **Vectrix 3.x and 4.0 cannot share a build.** Vectrix 3.x's single jar holds the same packages as 4.0's jars, so
  an application that also depends on Vectrix 3.x must move to 4.0 with this release
  ([Vectrix's migration guide](https://github.com/ljramones/vectrix/blob/v4.0.0/docs/migrating-to-4.0.md)).

## Install and consume

All public artifacts use version `1.13.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`: it depends on `org.dynamisengine:vectrix-ml:4.0.0`.
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix-render:4.0.0`.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

Vectrix 4.0.0 is distributed through the [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v4.0.0),
not Maven Central. Install it first. Since 4.0 it is a Maven repository ZIP, because its jars have a parent POM:

```sh
gh release download v4.0.0 --repo ljramones/vectrix \
  --pattern 'vectrix-4.0.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 vectrix-4.0.0-maven.zip
unzip vectrix-4.0.0-maven.zip
sh vectrix-4.0.0/install.sh

gh release download v1.13.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.13.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.13.0-maven.zip
unzip dynamisgpu-1.13.0-maven.zip
sh dynamisgpu-1.13.0/install.sh
```

Compare each ZIP digest against its `SHA256SUMS` before installation. The two releases have separate `SHA256SUMS`
files, so download them into separate directories. Existing 1.12.x artifacts are unchanged. The external
`dynamis-parent` stays at `1.0.1`. The class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (531 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 45 | 56 |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | 48 | 56 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 48 | 56 |

- **Cross-backend harness:** native Metal against MoltenVK passes.
- **vectrix-gpu:** Vectrix 4.0.0's vectrix-gpu uses `dynamis-gpu-api`, which this release does not change. Its
  3,094 tests pass on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6, unchanged) targets macOS 13.0 arm64.
The stricter runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
