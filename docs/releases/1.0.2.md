# DynamisGPU 1.0.2

Version 1.0.2 adds the JDK 25 headless compute foundation for the NeuralNetworks
adapter, graphics, and simulation consumers. This release is distributed through
GitHub and the local Maven repository. It is **not published to Maven Central**.

## Delivered

- Neutral providers/devices, retained buffers/slices, upload/download/copy/fill,
  mappings, ordered queues, pipelines/bindings, dispatch and bounded completion.
- Native Metal through JDK FFM and a versioned Objective-C C bridge, packaged for
  macOS arm64. Headless Vulkan executes actual SPIR-V compute pipelines.
- Shared conformance tests, dependent-dispatch examples, benchmark probes, and
  numerical/capability/lifetime documentation. Existing graphics APIs remain usable.
- JDK 25 builds, with source and Javadoc attachments for all library modules.

## Use from NeuralNetworks

The release build installs these exact coordinates locally:

| Artifact | Version | Purpose |
| --- | --- | --- |
| `org.dynamisengine:dynamis-gpu-api` | `1.0.2` | Neutral compute contracts |
| `org.dynamisengine:dynamis-gpu-metal` | `1.0.2` | Native Metal provider |
| `org.dynamisengine:dynamis-gpu-vulkan` | `1.0.2` | Vulkan provider |
| `org.dynamisengine:dynamis-gpu-test` | `1.0.2` | Optional mocks and conformance tests |

The release also includes `org.dynamisengine:dynamisgpu-parent:1.0.2`.
Its external parent remains `org.dynamisengine:dynamis-parent:1.0.1`.
Keep GPU dependencies in the optional NeuralNetworks GPU adapter/profile so CPU
users do not initialize or depend on a native backend. For native Metal:

```xml
<properties>
  <dynamisgpu.version>1.0.2</dynamisgpu.version>
</properties>
<dependencies>
  <dependency>
    <groupId>org.dynamisengine</groupId>
    <artifactId>dynamis-gpu-api</artifactId>
    <version>${dynamisgpu.version}</version>
  </dependency>
  <dependency>
    <groupId>org.dynamisengine</groupId>
    <artifactId>dynamis-gpu-metal</artifactId>
    <version>${dynamisgpu.version}</version>
  </dependency>
</dependencies>
```

Select `dynamis-gpu-vulkan` instead for Vulkan. Use
`--enable-native-access=ALL-UNNAMED` for class-path applications; named modules use
`org.dynamisengine.gpu.metal` and/or `org.lwjgl` as appropriate.
The runtime guide defines the [adapter handoff and shader ABI](../compute-runtime.md).
ML kernels, tensor operations, and Vectrix integration remain NeuralNetworks work.

## Install on another machine

Download the Maven repository ZIP and checksums from
[the v1.0.2 release](https://github.com/ljramones/DynamicGPU/releases/tag/v1.0.2):

```sh
gh release download v1.0.2 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.0.2-maven.zip' --pattern SHA256SUMS
# The checksum file also lists the optional standalone JAR downloads.
shasum -a 256 dynamisgpu-1.0.2-maven.zip
unzip dynamisgpu-1.0.2-maven.zip
sh dynamisgpu-1.0.2/install.sh
```

Compare the printed ZIP digest with `SHA256SUMS` before installing. The bundle
contains a Maven-layout file repository, parent/module POMs, runtime JARs, sources,
Javadocs, and an installer. Maven can alternatively consume its `repository/`
folder as a file repository. External dependencies resolve from Central normally;
the GitHub bundle makes version 1.0.2 available independently of Central publication.
The internal `dynamis-gpu-bench` module is excluded.

## Reproduce the release artifacts

On the validated macOS arm64 machine, select the Vulkan SDK loader/driver, then:

```sh
export VK_DRIVER_FILES="$HOME/VulkanSDK/1.4.341.0/macOS/share/vulkan/icd.d/MoltenVK_icd.json"
sh scripts/package-release.sh \
  -Ddynamisgpu.vk.loader="$HOME/VulkanSDK/1.4.341.0/macOS/lib/libvulkan.1.4.341.dylib"
```

This runs the full portable and required native hardware suites, installs artifacts
locally, stages them to a `file:` Maven repository under `target/release/`, and
creates the ZIP and SHA-256 checksums. It explicitly disables the Central release
profile. Do not use `deploy.sh` for this GitHub-only release.

## Validation and limits

The release build passed all 205 tests, including real Metal and Vulkan/MoltenVK
execution on Apple M4 Max. The download bundle was installed outside a Maven
project into a fresh cache; an independent Maven consumer resolved version 1.0.2
and verified 131 FP32 results from two dependent dispatches on each backend.
[Release verification evidence](../evidence/release-1.0.2.txt) includes the test
summaries, consumer results, and asset checksums. The implementation also includes
common examples and cost-separated host-clock benchmark probes.

Metal's included native bridge targets macOS 13.0, with execution verified on
macOS 27.0.1 arm64. Runtime MSL compilation is verified; offline `.metallib`
generation/loading awaits Xcode's Metal toolchain. Other OS/architecture paths
remain unverified. GPU timestamps and extra numerical features are not advertised.
See the [implementation record](../compute-implementation-record.md) for details.
