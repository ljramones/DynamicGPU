# DynamisGPU 1.0.3

Version 1.0.3 releases the floating-point fixes from `13c2a79` for consumers,
including vectrix-gpu and the NeuralNetworks GPU adapter. It is distributed through
GitHub and local Maven installation. It is not published to Maven Central.

## Changes

- Runtime MSL compilation on macOS 15+ uses safe math, precise functions, and a
  prepended `#pragma METAL fp contract(off)`. Multiplication and addition round
  separately by default; a shader can explicitly opt back into contraction.
- The Vulkan provider turns off MoltenVK fast math using `VK_EXT_layer_settings`
  when that extension is available. Consumers using the validated MoltenVK version
  no longer need `MVK_CONFIG_FAST_MATH_ENABLED=0` to preserve arithmetic and NaNs.
- The shared hardware conformance test checks reassociation, implicit fused
  multiply-adds, and NaN handling. Both backends passed on the M4 Max.

The [runtime guide](../compute-runtime.md) describes the numerical scope. Older
macOS retains its prior compilation behavior, offline Metal libraries keep their
own compiler settings, and SPIR-V controls contraction through `NoContraction`.
This is not a cross-backend bitwise guarantee for all numerical operations.

## Install and consume

All public artifacts use version `1.0.3` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`. Keep native backend dependencies
in the optional GPU adapter so CPU-only deployments remain independent.

```sh
gh release download v1.0.3 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.0.3-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.0.3-maven.zip
unzip dynamisgpu-1.0.3-maven.zip
sh dynamisgpu-1.0.3/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. The bundle includes
runtime JARs, POMs, sources, Javadocs, the native macOS arm64 bridge, and a Maven
repository installer. The internal benchmark module is excluded. External
dependencies continue to resolve from Maven Central normally.

Pin `1.0.3` for the API and selected backend. Existing 1.0.2 artifacts are unchanged.
The class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

The release build discovered 208 tests: 207 passed and one expected mock-only
floating-point test was skipped. All 14 tests on each hardware backend passed.
An independent Maven consumer installed the bundle into a fresh cache and verified
both dependent vector dispatches and floating-point regressions through the packaged
JARs, with `MVK_CONFIG_FAST_MATH_ENABLED` explicitly unset.
[Release evidence](../evidence/release-1.0.3.txt) records exact results and checksums.
There is no repository CI; these are local hardware results on Apple M4 Max,
macOS 27.0.1, with Vulkan through MoltenVK 1.4.1.

The included bridge targets macOS 13.0 arm64; the stricter runtime MSL behavior
requires macOS 15+. Offline metallib generation/loading and other platforms remain
unverified, as in 1.0.2. These limitations do not block this release for the tested
platform and runtime-compilation path.

Reproduce packaging without Central publication using `scripts/package-release.sh`
with the Vulkan SDK configuration from the [runtime guide](../compute-runtime.md).
