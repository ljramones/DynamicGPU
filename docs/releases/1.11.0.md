# DynamisGPU 1.11.0

Released 2026-11-25.

Version 1.11.0 completes milestone 1.11 of the [roadmap](../roadmap.md): attention at scale. Attention no longer
writes its scores to memory, decoding runs a kernel of its own, and keys and values can live in a paged cache shared
across sequences.

Like 1.10.1, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **Fused attention:** `AttentionF16.encode(encoder, q, k, v, o, shape)`, with no scratch buffers.
  - **What it is:** flash attention with an online softmax. Memory is linear in the sequence, and with the causal mask,
    key blocks no query sees are skipped.
  - **Kernels:**
    - a portable Slang kernel, for even head dimensions up to 256. On Vulkan at head dimension 128 it runs 16 lanes
      per row with interleaved dot products;
    - a Metal matrix kernel (`simdgroup_matrix`, hand-written MSL) for head dimensions 64 and 128;
    - a decode kernel for at most 8 rows per KV head, specialised to 1, 4 or 8 rows, with subgroup reductions where
      the device has them;
    - on native Metal, a one-dispatch short-context decode (head dimension 128, up to 512 keys).
  - **Fallbacks:** each optional kernel falls back to the portable one when a device or compiled pipeline can't run
    it.
  - **Key ranges:** with few rows, the keys are split across groups and combined in a second dispatch.
  - **Accuracy:** bounded (`fusedContract`). The tests check every element against the bound on all three backends.
- **Grouped-query attention:** `Shape.withKvHeads`. Query heads that share a KV head read each K and V block once.
- **KV caches:** `Shape.withCacheKeys` attends the first `keys` of a longer cache.
- **`PagedKvCache`:** keys and values in fixed-size pages of a pool, one K and one V pool per layer.
  - **Writing:** `reserve` grows a sequence, and `write` stores a layer's new keys and values.
  - **Sharing:** `fork` shares a sequence's pages (reference counts), with copy on write of a shared, partly filled page.
  - **Shortening:** `truncate`.
  - **Facts:** `stats()` gives free, pinned, evictable and shared pages. A sequence's tokens and pages are host-side and
    need no GPU sync.
  - **Attention:** `AttentionF16.encode(encoder, q, cache, layer, sequence, o, shape)` reads through the sequence's
    page table, bit for bit the contiguous result.
  - **Page tables:** a sequence's table is kept, immutable, until its pages change, so the layers of a step share it.
    Recorded commands keep the table they were recorded with.
- **Faster top-k sampling** (with or without top-p): small k uses a lower bound on the k-th logit to sort only the
  candidates, and larger k sorts short strides with subgroup shuffles. Draws stay bit for bit `Sampler.reference`.
  Top-k 40 with top-p at a vocabulary of 128256 drops from 76 us (1.10.1) to 41 to 47 us, depending on the logits.

## Measured

On an M4 Max, 32 heads with head dimension 128, FP16 O, whole encodes by GPU time with initialized inputs:

| Case | Composed (1.4.0) | Fused (1.11.0) |
|---|---|---|
| causal prefill, 512 tokens, Metal | 0.68 ms | 0.41 ms |
| causal prefill, 1024 tokens, Metal | 2.24 ms | 1.38 ms |
| causal prefill, 2048 tokens, Metal | 8.40 ms | 5.13 ms |
| causal prefill, 2048 tokens, MoltenVK | | 9.45 ms |
| decode, 8 KV heads, 512 keys, Metal | (no GQA) | 9.7 us |
| decode, 8 KV heads, 4096 keys, Metal | (no GQA) | 44.6 us |
| decode, 8 KV heads, 32768 keys, Metal | (no GQA) | 326 us |
| four layers of paged decode, 512 keys, Metal | | 20 us host, 61 us GPU, 90 us wall |

- **An independent review:** before release, a second agent reviewed the kernels for missed optimizations. Its
  report is in [optimization-results-1.11.md](../optimization-results-1.11.md). It found:
  - host recording costs: 3.9 ms of a paged decode step's encoding was re-reading kernel metadata and uploading page
    tables;
  - the short-context decode and the subgroup decode;
  - the Vulkan prefill layout;
  - the sampler's prefilter.
- **Checks:** the Metal numbers above were reproduced on the merged branch. The MoltenVK figure is the review's.
- **The alternatives that lost** are recorded in the [primitives guide](../primitives.md#attentionf16).

## Behaviour changes to check

- **`AttentionF16.Shape` has two more components:** `kvHeads` and `cacheKeys`.
  - **Still compatible:** the six-argument constructor and `of` keep their meaning (`kvHeads = heads`,
    `cacheKeys = keys`).
  - **Breaks:** a record pattern over `Shape` needs the new components.
  - **Changed:** `kBytes()` now counts `kvHeads * cacheKeys`.
- **The composed `encode` refuses grouped-query and cached shapes:** use the fused `encode` for those.
- **Summation order:** the subgroup and short-context decode kernels add their FP32 sums in a different order from
  the portable kernel. Results stay within `fusedContract`'s bound, but are not bit for bit across kernels.

## Known limits

- **One sequence per dispatch:** batched decode across sequences of different lengths, for continuous batching, is
  not done yet.
- **Group memory:** the fused kernels declare up to 26 KiB, more than the 16 KiB minimum, so devices with less refuse
  them (`fusedSupports`).

## Install and consume

All public artifacts use version `1.11.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.11.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.11.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.11.0-maven.zip
unzip dynamisgpu-1.11.0-maven.zip
sh dynamisgpu-1.11.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.10.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.
