# DynamisGPU 1.10.0

Released 2026-11-24.

Version 1.10.0 completes milestone 1.10 of the [roadmap](../roadmap.md): the kernels of a decode step around the
matrix products. With them, a step's norms, rotary embedding, activations, sampling and the next token's embedding
all run on the GPU, and the sampled token never has to return to the host.

Like 1.9.1, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **`Norms`:** RMSNorm and LayerNorm of each row, FP32 or FP16 in and out.
  - **Fused residual add:** the residual stream `h = x + res` is written exactly, in place or not, and normalized.
  - **Accuracy:** sums in a fixed tree; bounded by the device's rsqrt (`Norms.exact` in double).
- **`Rope`:** rotary position embedding, with both pair layouts and partial rotary dimensions.
  - **Tables:** cosines and sines come from a host table in double (`Rope.Table`: `standard`, `scaled`, or `of`
    for any scheme).
  - **Positions:** read from a GPU buffer.
  - **Exactness:** bit for bit `Rope.reference` on every device.
- **`Embedding`:** rows gathered by GPU-resident tokens from FP32, FP16 or quantized tables (any `QuantizedMatrix`
  format), bit for bit.
- **`Sampler`:** greedy, temperature, top-k (k up to 1024) and top-p on the GPU, from a seeded counter-based draw.
  - **On the GPU:** the token goes to a GPU buffer, which the next step's `Embedding` reads directly.
  - **Accuracy:** greedy is exact, and the same seed and step give the same token on a device.
  - **Across devices:** native Metal, MoltenVK and lavapipe matched `Sampler.reference` on every draw in the tests,
    and the draws follow the softmax.
- **Activations:** `Elementwise.Unary.SILU` and `GELU`, and `Elementwise.Binary.SWIGLU`.
- **`Reduce.logSumExp`:** per row, with a fixed-order max and sum.
- **Benchmark:** `-Dinference.benchmark=true` times a decode step's kernels.

## Fixed along the way

- **FP16 residual sums are rounded in integer arithmetic.** lavapipe folded `float(half(s))` back to `s`, so the
  norm used the unrounded sum while h held the rounded one.

## Behaviour changes to check

- **`Elementwise.Unary` and `Binary` gain values:** `SILU`, `GELU` and `SWIGLU`. A switch over them needs the new
  cases.

## Known limits

- **Sampling and log-sum-exp of a single row** run in one group: top-k 40 with top-p takes about 0.5 ms at a
  vocabulary of 128256 on an M4 Max, temperature-only sampling 51 us, and log-sum-exp 124 us. A multi-group form is
  planned.
- **The error check** that RoPE and the embedding gather run around their dispatch costs about 10 us per dispatch.

## Install and consume

All public artifacts use version `1.10.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.10.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.10.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.10.0-maven.zip
unzip dynamisgpu-1.10.0-maven.zip
sh dynamisgpu-1.10.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.9.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (TESTS_PORTABLE tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | TESTS_METAL_COMPUTE | TESTS_METAL_PRIM |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | TESTS_MVK_COMPUTE | TESTS_MVK_PRIM |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | TESTS_LVP_COMPUTE | TESTS_LVP_PRIM |

- **Cross-backend harness:** native Metal against MoltenVK passes.
- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6, unchanged) targets macOS 13.0 arm64.
The stricter runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
