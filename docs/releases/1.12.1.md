# DynamisGPU 1.12.1

Released 2026-11-25.

Version 1.12.1 runs 1.12.0's attention backward pass on Apple GPU matrix hardware. Every sum is still in a fixed order,
so gradients still do not depend on scheduling.

Like 1.12.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## Faster

`AttentionF16.backward` on native Metal at head dimensions 64 and 128 runs hand-written `simdgroup_matrix` kernels.

- **dQ:** 32-row groups over 32-key blocks.
- **dK and dV:** 32-key groups over 16-row tiles.

On an M4 Max, 32 heads, head dimension 128, causal, FP16 O:

| Sequence | 1.12.0 (portable) | 1.12.1 (matrix) |
|---|---|---|
| 512 | 3.50 ms | 2.84 ms |
| 1024 | 13.2 ms | 9.84 ms |
| 2048 | 51.5 ms | 37.8 ms |

- **Alternatives that lost:**
  - dQ over key blocks of 16: the same time;
  - K and V held in registers for dK and dV: slower.

  The [primitives guide](../primitives.md#attention-the-training-forward-pass-and-the-backward-pass) has the details.
- **What is left:** each kernel still takes 3 to 4 times the forward pass's time for 1.5 to 2 times its matrix work.

## Behaviour changes to check

- **FP16 roundings on Metal.** The matrix kernels round dO, P and dS to FP16 for their products, as the forward matrix
  path rounds P. The bound (`backwardContract`) includes these roundings, and the tests check every gradient element
  against it; the worst measured error is 81 % of it.
- **FP32 P and dS are still available.** Reproducible mode (`-Ddynamisgpu.reproducible=true`) and every other device
  run the portable kernels.

## Install and consume

All public artifacts use version `1.12.1` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.12.1 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.12.1-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.12.1-maven.zip
unzip dynamisgpu-1.12.1-maven.zip
sh dynamisgpu-1.12.1/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.12.0 artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (PORTABLE tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 45 | PRIM |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | 48 | PRIM |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 48 | PRIM |

- **Both backward paths on Metal:** the tests run the matrix kernels and, through a test switch, the portable ones.
- **Cross-backend harness:** native Metal against MoltenVK passes.
- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6, unchanged) targets macOS 13.0 arm64.
The stricter runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
