# DynamisGPU 1.6.0

Released 2026-11-24.

Version 1.6.0 completes milestone 1.6 of the [roadmap](../roadmap.md), the second runtime layer:
- observability hooks for cost models;
- timeline fences;
- a transfer queue;
- indirect dispatch;
- transient arenas;
- interop with engine renderers.

Like 1.5.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **Observability hooks for cost models** ([compute-runtime.md](../compute-runtime.md)):
  - dispatch labels joined `outer/inner`, with the primitives labelling their own dispatches;
  - `GpuSubmission.dispatchTimings()`;
  - submission and recording names, and recording tags;
  - memory classes (`BufferDescriptor.label`, `GpuDevice.memoryByLabel()`);
  - queue counters (`GpuQueue.stats()`).

  All are host-side and never wait for the device.
- **Timeline fences:** `GpuDevice.fence()`, `GpuFence`, `GpuCommandEncoder.waitFor` and `signal`, and the same on
  `GpuRecording`. They use Vulkan timeline semaphores and Metal shared events, and are tested on native Metal,
  MoltenVK and lavapipe.
- **Interop:** `GpuDevice.interop()` and `GpuInterop`, for an engine renderer on the same GPU.
  - **Native handles:** the device and queue, buffers with their pooled offset and size, and fences.
  - **Vulkan `recordInto`:** records an encoder's commands into a command buffer the caller owns and submits.
- **Transient arenas:** `GpuDevice.arena`, `GpuArena` and `GpuArena.Scope`. Scoped bump allocation over one
  buffer, reused in compute-queue order, with `used()` and `highWater()`.
- **Indirect dispatch:** `GpuCommandEncoder.dispatchIndirect` and `BufferUsage.INDIRECT`. Group counts come from a
  GPU buffer, possibly written earlier in the same submission.
- **A transfer queue:** `GpuDevice.queue(QueueKind.TRANSFER)`, `GpuQueue.kind()` and `dedicated()`.
  - **Hardware:** a second Metal command queue, or a dedicated Vulkan transfer family, with buffers shared
    concurrently.
  - **Ordering:** order work across queues with fences.
  - **Counters:** `stats()` is per queue.
- **Debug labels in captures:** Vulkan `VK_EXT_debug_utils` regions (enabled on the instance where offered) and Metal
  debug groups.

## Behaviour changes to check

- **Metal bridge ABI 5:** it adds:
  - `dg_compute_label`;
  - the `dg_event_*` and `dg_batch_*_event` fence calls;
  - `dg_batch_create_on` (the transfer queue);
  - `dg_compute_dispatch_indirect`;
  - the `dg_*_native` interop accessors.
- **Vulkan devices:** they enable `timelineSemaphore` where supported, and create a transfer queue on a dedicated
  transfer family when there is one. Pool blocks are then created with concurrent sharing.
- **`GpuQueue.stats()` counts per queue** (compute and transfer separately).
- **`ComputeDriver.Dispatch` gains `label` and `indirect` components.** The 5- and 6-argument constructors remain,
  and `withParameters`, `withGroups` and `withBindings` keep the rest.
- **`BufferUsage` gains `INDIRECT`.** Vulkan pool blocks now also have the indirect-buffer usage.
- **`BufferDescriptor` gains a `label` component.** The 3-argument constructor remains, and record patterns
  deconstructing it need the fourth component.

## Install and consume

All public artifacts use version `1.6.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.6.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.6.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.6.0-maven.zip
unzip dynamisgpu-1.6.0-maven.zip
sh dynamisgpu-1.6.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.5.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (388 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance (incl. queues, fences, indirect, arenas, interop) | Primitives |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 41 | 16 |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | 44 | 16 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 44 | 16 |

- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Not measured here: transfer-queue overlap on a discrete GPU. On the M4 Max's unified memory it brings no gain.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 5) targets macOS 13.0 arm64. The stricter
runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
