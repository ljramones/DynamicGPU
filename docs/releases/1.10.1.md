# DynamisGPU 1.10.1

Released 2026-11-24.

Version 1.10.1 makes 1.10.0's sampling and log-sum-exp fast for a single row. Both ran a row in one group, which
left most of the GPU idle during a decode step. Now each row is spread across groups.

Like 1.10.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## Faster

Times are for a vocabulary of 128256 on an M4 Max:

| Kernel | 1.10.0 | 1.10.1 |
|---|---|---|
| sampling, greedy | 19 us | 12 us |
| sampling, temperature only | 51 us | 17 us |
| sampling, top-k 40 + top-p 0.95 | 526 us | 76 us |
| `Reduce.logSumExp` | 124 us | 10 us |

- **`Sampler`:** now runs in stages.
  - **Stage 1:** one group per chunk of 1024 logits finds the chunk's max, argmax and weight sum. With top-k or
    top-p, it also sorts the chunk into runs of 256.
  - **Merge rounds (top-k and top-p only):** each round merges sorted lists in a pairwise tree and keeps the first k.
  - **Stage 2:** one group per row combines the chunks and draws.
  - **The same rules as 1.10.0:** k up to 1024, ties in index order, NaN as -infinity.
- **`Reduce.logSumExp`:** a row longer than 4096 is split into chunks of 4096, one group each. A second dispatch
  combines them as `M + log(sum s exp(m - M))`, in a fixed tree. The accuracy bound is unchanged.

## Behaviour changes to check

- **The unrestricted draw is hierarchical.** Without top-k and top-p, a chunk is drawn by its total weight, then a
  token within it. The order is still the index order, but the running sums round differently. So for the same seed
  and step, a token can differ from 1.10.0's where the draw falls within rounding of a boundary.
  `Sampler.reference` follows the new order.
- **Scratch memory:** each `Sampler.encode` and `Reduce.logSumExp` allocates scratch buffers for its recorded
  commands.
  - **Sampling:** 16 bytes per chunk of each row. With top-k or top-p, also 16 KiB per chunk.
  - **Log-sum-exp:** 8 bytes per chunk.

## Install and consume

All public artifacts use version `1.10.1` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.10.1 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.10.1-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.10.1-maven.zip
unzip dynamisgpu-1.10.1-maven.zip
sh dynamisgpu-1.10.1/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.10.0 artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

- **Portable build:** passes (488 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives |

  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | 48 | 41 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 48 | 41 |

- **Sampler draws:** in the tests, every draw on all three backends matched `Sampler.reference`.
- **Cross-backend harness:** native Metal against MoltenVK passes.
- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6, unchanged) targets macOS 13.0 arm64.
The stricter runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
