# DynamisGPU 1.3.0 (unreleased)

Draft notes, collected as the work lands.

## New

- **GPU timestamps:** `GpuSubmission.gpuTime()` gives a completed submission's GPU execution time.
  - **Where it's reported:** `GpuCapabilities.timestamps()` is now true where the device can measure it: native Metal,
    MoltenVK and lavapipe. See [compute-runtime.md](../compute-runtime.md).
  - **Benchmark:** the `GemmF16` benchmark reports GFLOP/s by GPU time.

- **Matrix hardware:** the capability `SUBGROUP_MATRIX_F16` reports Metal SIMD-group matrices on Apple7 and later
  GPUs. `CapabilityTierConformance` checks it exactly.
- **`GemmF16` algorithms:**
  - **`SIMDGROUP_MATRIX`:** a new hand-written MSL kernel. It runs at 12.9 TFLOP/s at 4096³ on an M4 Max, 2.3 times
    the tiled kernel. It is held to the same bound, and on the M4 Max it measured bit-identical to the reference.
  - **Choosing:** `create(device)` picks the fastest algorithm; `create(device, algorithm)` and `supports` choose
    explicitly. `TILED` stays the reproducible default elsewhere.
- **Vulkan cooperative matrices are not included:** no available driver (MoltenVK, lavapipe) supports them.

## Behaviour changes to check

- **`GemmF16.create(device)` on Apple GPUs:** it now picks `SIMDGROUP_MATRIX` on native Metal. Pass `Algorithm.TILED`
  for results that match other devices by contract.

- **Metal bridge ABI 3:** it adds `dg_gpu_seconds`. A bridge built from 1.2 sources is refused with an ABI mismatch.
- **Vulkan query pools:** each Vulkan submission creates a two-entry timestamp query pool where the queue supports
  timestamps.
