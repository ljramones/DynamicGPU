# DynamisGPU 1.3.0

Released 2026-11-24.

Version 1.3.0 adds two things:
- **GPU timestamps:** submissions report how long they ran on the GPU.
- **Matrix hardware on Apple GPUs:** `GemmF16` gets a SIMD-group matrix kernel that runs 2.3 times faster than the
  tiled one.

Like 1.2.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **GPU timestamps:** `GpuSubmission.gpuTime()` gives a completed submission's GPU execution time.
  - **What it covers:** the start of the first command to the end of the last, excluding queueing and host work.
  - **Where it's reported:** `GpuCapabilities.timestamps()` is now true where the device can measure it: native Metal,
    MoltenVK and lavapipe. See [compute-runtime.md](../compute-runtime.md).
  - **Benchmark:** the `GemmF16` benchmark reports GFLOP/s by GPU time.
- **Matrix hardware:** the capability `GpuCapabilities.SUBGROUP_MATRIX_F16` reports Metal SIMD-group matrices on
  Apple7 and later GPUs. `CapabilityTierConformance` checks it exactly.
- **`GemmF16` algorithms** ([primitives.md](../primitives.md)):
  - **`SIMDGROUP_MATRIX`:** a new hand-written MSL kernel, because Slang cannot emit Metal SIMD-group matrices.
    - **Speed:** 12.9 TFLOP/s at 4096³ on an M4 Max, 2.3 times the tiled kernel.
    - **Accuracy:** it is held to the same bound.
    - **Exactness:** on the M4 Max it measured bit-identical to `GemmF16.reference`. That is a measurement, not a
      promise.
  - **`TILED`:** the 1.2 kernel. It is reproducible on every device by contract.
  - **Choosing:** `create(device)` picks the fastest algorithm. `create(device, algorithm)` and `supports(device,
    algorithm)` choose explicitly.

## Not included

- **Vulkan cooperative matrices:** Slang emits `CooperativeMatrixKHR`, but neither MoltenVK nor lavapipe supports
  `VK_KHR_cooperative_matrix`. They wait for NVIDIA, AMD or Intel hardware to test on.

## Behaviour changes to check

- **`GemmF16.create(device)` on Apple GPUs:** it now picks `SIMDGROUP_MATRIX` on native Metal. Pass `Algorithm.TILED`
  for results that match other devices by contract.
- **Metal bridge ABI 3:** it adds `dg_gpu_seconds`. A bridge built from 1.2 sources is refused with an ABI mismatch.
- **Vulkan query pools:** each Vulkan submission creates a two-entry timestamp query pool where the queue supports
  timestamps.
- **`dynamis-gpu-vectrix`:** it now depends on Vectrix 3.3.0 (was 3.2.1).

## Install and consume

All public artifacts use version `1.3.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.3.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.3.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.3.0-maven.zip
unzip dynamisgpu-1.3.0-maven.zip
sh dynamisgpu-1.3.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.2.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (317 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target:

  | Target | Driver | Compute conformance (incl. tiers) | GemmF16 (both algorithms where supported) |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 32 | 4 (benchmark opt-in) |
  | MoltenVK | 1.4.1 on the same machine | 33 | 4 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 33 | 4 |

- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 3) targets macOS 13.0 arm64. The stricter
runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
