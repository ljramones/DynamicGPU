# DynamisGPU 1.14.1

Released 2026-11-25.

Fused `AttentionF16` accepts GPU-resident valid key lengths for padded inference and training batches.
NNJava can pass the length buffer to forward and backward on native Metal and Vulkan without recording
the intermediate score or probability matrices. [NNJava adapter example](../primitives.md#valid-key-lengths-1141)

## API and accuracy

- Use the overloads ending in `shape, lengths, lengthGroup` for dense forward, training forward, training backward,
  and single-sequence paged attention. Batched paged decode ends in `decodeBatch, lengths, lengthGroup`.
- Supply unsigned 32-bit lengths, one per group of query heads. In batched decode the index is
  `(sequenceIndex * heads + head) / lengthGroup`. One length per sequence uses `lengthGroup = headsPerSequence`.
  Preserve the buffer contents until both forward and backward have consumed them.
- The length limits keys for every query row in the group. A causal row also uses its original offset
  `physicalKeys - queries`. Length zero produces positive-zero output, negative-infinity log-sum-exp and zero gradient
  contributions. Values beyond the key count admit the whole physical sequence.
- The existing numerical bounds apply to the visible keys. The full-length and unmasked calls retain their
  rounding rules. There is no dense additive-bias input to this API. The standalone softmax and GEMM composition
  remains available for other score transformations.
- The earlier paged-decode working-set and CPU codec study is included. FP16 remains the cache storage format.
  Four-bit values accounted for most of the synthetic outlier error. [Study and measurements](../paged-kv-study.md)

## Measured

On an Apple M4 Max, 16 query and KV heads, 512 causal queries and keys, dimension 128, and FP16 output,
four sequences contributed valid key lengths of 512, 384, 128 and zero. GPU times are medians of four warmed,
alternating pairs of whole submissions. The composed path uses the 1.14.0 GEMM, valid-length softmax and value GEMM.

| Backend | Fused | Composed |
|---|---:|---:|
| Native Metal | 238.5 µs | 350.9 µs |
| MoltenVK | 275.2 µs | 644.6 µs |

Run `MetalAttentionTest#benchmarkMaskedPrefill` or `VulkanAttentionTest#benchmarkMaskedPrefill` in the corresponding
hardware profile with `-DattentionMask.benchmark=true`. The test also prints host recording and wall time.

The first implementation checked for a mask at runtime in the decode kernels. An interleaved comparison on
MoltenVK found that this added 2–3% to unmasked decode over 1.14.0. The release specializes the decode pipeline
when it first sees a masked or unmasked call. Both cases retain the same accumulation order and bounds.

| Keys | Runtime mask check | Specialized unmasked decode |
|---:|---:|---:|
| 512 | 41.00 µs | 38.60 µs |
| 4,096 | 62.05 µs | 59.25 µs |
| 32,768 | 361.05 µs | 349.05 µs |

These are means from two JVMs per implementation on the same M4 Max, in alternating order, with 32 query
heads, eight KV heads and dimension 128. With masks enabled, the 4K comparison varied in direction across the
two runs (51.94 and 52.58 µs overall). The 512- and 32K-key masked means were 39.55 and 244.42 µs with specialization.

In the final native Metal run, unmasked decode at 32K keys took 337.7 µs versus 337.6 µs on 1.14.0.
At 2,048 causal tokens, unmasked backward took 38.85 ms versus 37.55 ms on Metal and 151.79 ms versus
147.53 ms on MoltenVK. These training controls are single process comparisons.

## Direct shader bindings

The Java methods supply every binding. Consumers dispatching bundled kernels directly must use the matching
1.14.1 manifest. Forward appends `lengthGroup` after `writeLse`. Backward reuses the former `pad0`.
Zero in this field selects the unmasked path. Fixed-tree and subgroup decode also expose a uint32
`USE_LENGTHS` specialization (ID 1, default 1). The Java methods set it to 0 for absent lengths and 1 otherwise.

| Kernel | Buffer slots in order, starting at zero |
|---|---|
| Portable and native matrix flash | Q, K, V, O, partials, page table, LSE, lengths |
| Fixed-tree and subgroup decode | Q, K, V, O, partials, page table, lengths |
| Native Metal short decode | Q, K, V, O, page table, lengths |
| Split combine | partials, O, LSE |
| Backward dot | O, dO, dot scratch, lengths |
| Backward dQ | Q, K, V, dO, LSE, dot scratch, dQ |
| Backward dK/dV | Q, K, V, dO, LSE, dot scratch, dK, dV |

The split scratch uses one FP32 buffer. The first `2 * splits * totalRows` words hold per-split maxima and sums,
followed by `splits * totalRows * headDim` accumulator words. The backward dot prepass writes a float per row,
then one clamped uint32 length per group for masked calls. These layouts keep all kernels within eight storage bindings.

## Install and consume

All public artifacts use version `1.14.1` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`: it depends on `org.dynamisengine:vectrix-ml:4.0.0`.
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix-render:4.0.0`.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

Vectrix 4.0.0 comes from the [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v4.0.0), as a
Maven repository ZIP. Install it first:

```sh
gh release download v4.0.0 --repo ljramones/vectrix \
  --pattern 'vectrix-4.0.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 vectrix-4.0.0-maven.zip
unzip vectrix-4.0.0-maven.zip
sh vectrix-4.0.0/install.sh

gh release download v1.14.1 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.14.1-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.14.1-maven.zip
unzip dynamisgpu-1.14.1-maven.zip
sh dynamisgpu-1.14.1/install.sh
```

Compare each ZIP digest against its `SHA256SUMS` before installation; download the two releases into separate
directories. The external `dynamis-parent` stays at `1.0.1`. The class-path
JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification

- The JDK 25 portable reactor passed `mvn -o verify`. Surefire reported 565 cases, with 292 executed and 273 skipped, including hardware-gated tests.
- The full Slang rebuild completed successfully with the Vulkan SDK 1.4.341.0 toolchain. The manifest tests check the eight-binding ceiling and group memory limits.
- Native Metal, MoltenVK and Linux lavapipe checked every tested masked output and gradient against the documented bounds, including empty rows, grouped heads sharing KV, a non-dividing length group, a split with no visible keys, and poisoned padding. The new masked forward cases reached at most 0.725 of their bound on each backend. The new masked backward cases reached 0.335 on Metal and 0.166 on MoltenVK and lavapipe.
- The tests cover both FP16 and FP32 output, the forced fixed-tree decode and scalar backward paths, nonuniform paged batches, and equivalence of representative full-length and unmasked forward results.

| Local target | Driver | Attention cases executed |
|---|---|---:|
| Native Metal | Apple M4 Max, macOS 27.0.1 | 20 with feature and performance checks enabled |
| MoltenVK | 1.4.1, same M4 Max | 20 with feature and performance checks enabled |
| Linux lavapipe | llvmpipe LLVM 20.1.2, Vulkan 1.4.318 | 16 correctness cases |

The standard hardware run excludes five opt-in benchmarks. The Apple release runs additionally exercise
the dedicated Vulkan transfer queue and cross-backend conformance.
