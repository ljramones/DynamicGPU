# DynamisGPU 1.7.0 (unreleased)

Draft notes, collected as the work lands. Milestone 1.7 of the [roadmap](../roadmap.md): the kernel kit.

## New

- **The kernel kit** (`org.dynamisengine.gpu.api.compute.kit`): the host-side plumbing every kernel family shares.
  - **`ParameterLayout`:** parameter blocks written by field name, checked against the kernel's manifest. A field
    with the wrong type, written twice or not written is an error.
  - **`StridedView`:** an element view of a buffer, with an offset, extents and strides.
    - **Layouts:** dense, sliced, transposed, batched, broadcast, interleaved and structure-of-arrays.
    - **Checks:** one bounds check on the largest index it reaches (`check`), and an aliasing check for outputs
      (`isWritable`).
    - **Parameters:** a view writes its own parameter fields (`Block.view`).
  - **`Grid`:** linear group ranges folded into the device's group-count limits.
  - **`PipelineSet`:** pipelines compiled and closed together, with a placeholder buffer for absent optional
    arguments.
  - **`Checks`:** argument checks and the 32-bit index limit.
- **Specialization on every backend:** Metal gains function constants (bridge ABI 6), joining Vulkan's
  specialization constants.
  - **Manifest:** ShaderBuild records each kernel's constants.
  - **Specializing:** `KernelLibrary.pipeline(..., Map<String, ?> constants)` sets them by name.
  - **Reading them:** `KernelLibrary.constants(kernel)`.
- **Limits for tile heuristics:**
  - `GpuCapabilities.maxGroupSharedBytes()`;
  - `GpuComputePipeline.limits()` (`PipelineLimits`: max threads, execution width, group-shared bytes);
  - `KernelLibrary.groupSharedBytes(kernel)`;
  - `spi.SpirvModule.workgroupBytes`.
- **A Slang include library** (`dynamis/kit.slang`), bundled in `dynamis-gpu-shaders` and put on every ShaderBuild
  include path. Its hash is recorded as `include.sha256`. It has:
  - grids;
  - strided views with broadcasting;
  - fixed-tree group reductions and scans that respect Slang's groupshared reread rules;
  - Java-semantics max and min;
  - classification by bits;
  - error reporting.
- **New primitives:** `Elementwise`, `Reduce` (sum, max, min, argmax), `Scan` and `NanCheck` (with tripwires).
  - **Inputs:** strided views of rank up to 4.
  - **Accuracy:** the reductions and scans match their CPU references bit for bit on every device, and every
    operation is checked against its contract on native Metal, MoltenVK and lavapipe.
  - Details are in [primitives.md](../primitives.md).
- **`AccuracyContract`** (kit): an operation's contract as data, with its inputs, accumulation, output rounding,
  order class and bound.
  - **Where:** every new primitive publishes one.
  - **Helper:** `ulpDistance`.
- **The primitives use the kit:** `GemmF16` and `Softmax` write their parameters through `ParameterLayout`.

## Behaviour changes to check

- **Metal bridge ABI 6:** it adds:
  - `dg_pipeline_create_specialized`;
  - `dg_pipeline_limits`;
  - `dg_device_group_memory`.

  A kernel that declares function constants is now always specialized, so its constants take their source defaults.
- **`GpuCapabilities` gains a `maxGroupSharedBytes` component.** The 13- and 11-argument constructors remain and
  assume 16 KiB.
- **`KernelAbi` (dynamis-gpu-shaders) gains a `constants` component.**

- **Closing a failed submission no longer rethrows its failure.** `GpuSubmission.close()` still waits for completion,
  and still throws `TIMEOUT` if the submission stays pending. The failure is reported by `await`, `status` and
  `failure()`; rethrowing it from `close` made try-with-resources throw a duplicate, or mask the caller's own
  exception.
- **Argument errors** from `GemmF16` and `Softmax` have reworded messages; the exception types are unchanged.
