# DynamisGPU 1.7.0

Released 2026-11-24.

Version 1.7.0 completes milestone 1.7 of the [roadmap](../roadmap.md), the kernel kit. It is the shared plumbing,
Slang library, validation tools and accuracy contracts that the GEMM family, quantization and the inference kernels
of the next milestones build on. It adds four primitives: elementwise maps, reductions, scans and a NaN check.

Like 1.6.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **The kernel kit** (`org.dynamisengine.gpu.api.compute.kit`): the host-side plumbing every kernel family shares.
  - **`ParameterLayout`:** parameter blocks written by field name, checked against the kernel's manifest. A field
    with the wrong type, written twice or not written is an error.
  - **`StridedView`:** an element view of a buffer, with an offset, extents and strides.
    - **Layouts:** dense, sliced, transposed, batched, broadcast, interleaved and structure-of-arrays.
    - **Checks:** one bounds check on the largest index it reaches (`check`), and an aliasing check for outputs
      (`isWritable`).
    - **Parameters:** a view writes its own parameter fields (`Block.view`).
  - **`Grid`:** linear group ranges folded into the device's group-count limits.
  - **`PipelineSet`:** pipelines compiled and closed together, with a placeholder buffer for absent optional
    arguments.
  - **`Checks`:** argument checks and the 32-bit index limit.
- **Specialization on every backend:** Metal gains function constants (bridge ABI 6), joining Vulkan's
  specialization constants.
  - **Manifest:** ShaderBuild records each kernel's constants.
  - **Specializing:** `KernelLibrary.pipeline(..., Map<String, ?> constants)` sets them by name.
  - **Reading them:** `KernelLibrary.constants(kernel)`.
- **Limits for tile heuristics:**
  - `GpuCapabilities.maxGroupSharedBytes()`;
  - `GpuComputePipeline.limits()` (`PipelineLimits`: max threads, execution width, group-shared bytes);
  - `KernelLibrary.groupSharedBytes(kernel)`;
  - `spi.SpirvModule.workgroupBytes`.
- **A Slang include library** (`dynamis/kit.slang`), bundled in `dynamis-gpu-shaders` and put on every ShaderBuild
  include path. Its hash is recorded as `include.sha256`. It has:
  - grids;
  - strided views with broadcasting;
  - fixed-tree group reductions and scans that respect Slang's groupshared reread rules;
  - Java-semantics max and min;
  - classification by bits;
  - error reporting.
- **New primitives:** `Elementwise`, `Reduce` (sum, max, min, argmax), `Scan` and `NanCheck` (with tripwires).
  - **Inputs:** strided views of rank up to 4.
  - **Accuracy:** the reductions and scans match their CPU references bit for bit on every device, and every
    operation is checked against its contract on native Metal, MoltenVK and lavapipe.
  - Details are in [primitives.md](../primitives.md).
- **`AccuracyContract`** (kit): an operation's contract as data, with its inputs, accumulation, output rounding,
  order class and bound.
  - **Where:** every new primitive publishes one.
  - **Helper:** `ulpDistance`.
- **Validation and debugging:**
  - **Debug builds** (`-Ddynamisgpu.kernels.debug=true`, or `KitOptions.run`/`call` for one task).
    - **The switch:** the kit's `DG_DEBUG` specialization constant (id 100) turns on `dg_in_range`. Normal pipelines
      compile the checks out.
    - **What they check:** every access of the kit primitives, against the buffer's length.
    - **Reporting:** an out-of-range access is reported as `DG_ERROR_INDEX` through a `KernelErrors` buffer, so the
      submission fails with `KERNEL_ERROR` instead of corrupting a neighbouring pooled buffer.
    - **Tested:** debug builds give the same bits as normal ones.
  - **Reproducible mode** (`-Ddynamisgpu.reproducible=true`): `GemmF16.create` and `AttentionF16.create` choose the
    fixed-order `TILED` algorithm.
  - **NaN tripwires:** `NanCheck.tripwire`.
  - **A cross-backend harness** (`dynamis-gpu-test`'s `CrossBackend`): it runs one operation on two devices and
    reports the first element beyond the operation's contract.
    - **In CI:** native Metal is compared with MoltenVK.
    - **Measured:** `Reduce`, `Scan` and `Elementwise` EXP agree bit for bit.
- **`ShapeRegistry`** (kit): it picks a kernel variant by shape and device from measured costs, and
  `checkLimits` verifies every variant against the pipeline's and the device's limits.
  - **`GemmF16.create(device)` now dispatches per shape:**
    - **The rule:** TILED for `m < 64`, unless B is transposed and `m <= 16`; the matrix kernel otherwise.
    - **Measured:** TILED is up to 1.9 times faster on skinny products.
    - **Querying it:** `algorithm(shape)` reports the choice.
- **Contracts for the existing primitives:** `GemmF16.contract(algorithm, output)`, `Softmax.contract(output)` and
  `AttentionF16.contract()`.
- **The primitives use the kit:** `GemmF16` and `Softmax` write their parameters through `ParameterLayout`.

## Behaviour changes to check

- **`GemmF16.create(device)` on matrix-hardware devices** compiles both algorithms and runs TILED for skinny shapes.
  - **Results:** they stay within the same contract.
  - **`algorithm()`:** it still names the large-shape algorithm; `algorithm(shape)` gives the per-shape one.
  - **Fixing one algorithm:** `create(device, algorithm, output)` keeps a single one.

- **Metal bridge ABI 6:** it adds:
  - `dg_pipeline_create_specialized`;
  - `dg_pipeline_limits`;
  - `dg_device_group_memory`.

  A kernel that declares function constants is now always specialized, so its constants take their source defaults.
- **`GpuCapabilities` gains a `maxGroupSharedBytes` component.** The 13- and 11-argument constructors remain and
  assume 16 KiB.
- **`KernelAbi` (dynamis-gpu-shaders) gains a `constants` component.**

- **Closing a failed submission no longer rethrows its failure.** `GpuSubmission.close()` still waits for completion,
  and still throws `TIMEOUT` if the submission stays pending. The failure is reported by `await`, `status` and
  `failure()`; rethrowing it from `close` made try-with-resources throw a duplicate, or mask the caller's own
  exception.
- **Argument errors** from `GemmF16` and `Softmax` have reworded messages; the exception types are unchanged.

## Install and consume

All public artifacts use version `1.7.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.7.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.7.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.7.0-maven.zip
unzip dynamisgpu-1.7.0-maven.zip
sh dynamisgpu-1.7.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.6.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (428 tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives (GEMM, softmax, attention, kit) |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | 44 | 25 |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | 47 | 25 |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | 47 | 25 |

- **Cross-backend harness:** native Metal against MoltenVK; `Reduce`, `Scan` and EXP agree bit for bit.
- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6) targets macOS 13.0 arm64. The stricter
runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
