# DynamisGPU 1.8.0

Released 2026-11-24.

Version 1.8.0 completes milestone 1.8 of the [roadmap](../roadmap.md), the GEMM family. `GemmF16` grows from one
dense multiply into the family an inference and training stack needs:
- decode at close to memory bandwidth;
- small and grouped multiplies;
- the weight gradient;
- fused epilogues;
- BF16 and FP32 inputs.

Every fixed-order form is bit for bit a CPU reference on native Metal, MoltenVK and lavapipe.

Like 1.7.0, it is distributed through GitHub and local Maven installation, not Maven Central.

## New

- **Skinny GEMM for decode** (`GemmF16.Algorithm.SKINNY`, `m <= 16`): B is streamed once with every row of A.
  - **Speed:** at `m = 1` with B transposed (the weights of a linear layer) it streams 378-408 GB/s on an M4 Max.
    That is 77-96 % of the measured streaming-read bandwidth, and about 7 times the tiled kernel, which was at
    53 GB/s.
  - **Measuring it:** `-Dgemm.decode=true` reports GB/s of B and the share of the streaming-read bandwidth, measured
    in the same run.
  - **The vector build:** aligned operands with B transposed are read 16 bytes per lane.
  - **Order:** fixed, so the result is the same bits on every device: k is dealt to 32 lanes in chunks of 8 (16 in
    chunks of 2 without B transposed), each lane sums in order, and the lanes combine in a fixed tree.
    `GemmF16.referenceSkinny` and `referenceSkinnyF16` compute the same bits on the CPU.
- **Small multiplies** (`Algorithm.SMALL`): 16 x 16 tiles, one element per thread, summing in order of k.
  - **Exactness:** bit for bit `reference`.
  - **Speed:** on batches of 16 x 16 and 32 x 32 multiplies it takes 0.26 and 0.62 of TILED's time. It wins too
    wherever TILED's 64 x 64 tiles are too few to fill the GPU: 0.29 at 128^3.
- **Grouped GEMM** (`encodeGrouped`): many multiplies of different shapes in one dispatch, such as the experts of a
  mixture-of-experts layer.
  - **The table:** a `Problem` table of sizes, leading dimensions and offsets, which a kernel may write, such as a
    router. `Grouped` holds what the problems share.
  - **Exactness:** each problem runs the tiled kernel, so it is bit for bit `referenceGrouped`. Empty problems cost
    nothing.
  - **Safety:** a problem that reaches outside its buffers is skipped and fails the submission with `KERNEL_ERROR`.
- **Transposed A** (`Shape.transposeA`, `Shape.ofTransposedA`): `C = A^T B`, the weight gradient. Every algorithm
  but SKINNY takes it.
- **Fused epilogues** (`GemmF16.Epilogue`), applied in FP32 before the one output rounding:
  - **Steps:** bias (per column or row), an activation (ReLU, GELU in its tanh form, SiLU), a gate
    (`Epilogue.swiGlu()`), and a residual add.
  - **API:** `encode(encoder, a, b, c, shape, epilogue, bias, gate, residual)`.
  - **Exactness:** bias, ReLU, gate and residual keep the fixed-order kernels bit for bit with
    `reference(algorithm, ...)`. GELU and SiLU use the device's `exp` and are bounded.
- **BF16 and FP32 inputs** (`GemmF16.Input`; `create(device, input, output)`) on every family.
  - **BF16:** it widens exactly and is never narrowed to FP16.
  - **FP32:** each step is one fused multiply-add. It is bit for bit the references (`Math.fma`) where the device
    reports `FUSED_FMA` (native Metal, MoltenVK), and within the bound on lavapipe.
  - **The Metal matrix kernel:** it gains FP32 entries.
  - **API:** `GemmF16.Elements` reads A and B for the references, and `bf16ToFloat` and `floatToBf16` convert.
- **Column-major products:** `Shape.columnMajor` describes them as the row-major `C^T = op(B)^T op(A)^T`.
- **Shape dispatch by estimated time:** `GemmF16.create(device)` compiles every algorithm the device runs, all or
  none, and the registry picks one per shape.
  - **The costs:** estimated GPU times (`GemmF16.Costs`), fitted to sweeps on an M4 Max.
  - **Checked:** on all 46 measured shapes they pick the fastest algorithm or one within 1.2 times of it
    (`GemmF16Test.costModelPicksTheMeasuredFastest`).
- **Contracts per form:** `contract(algorithm, input, output, epilogue)` states the inputs, the accumulation (FP32
  for every input), the order class and the bound.
- **`ComputeConformance.runsLongCommandLists`:** 5,000 dependent dispatches in one submission, and as a replayed
  recording, on every backend.

## Fixed

- **Vulkan: submissions of more than about 1,170 dispatches failed.** Preparing a batch allocated every dispatch's
  descriptor-set information in the one LWJGL thread-stack frame that spans the command list. Past 64 KiB that threw
  `OutOfMemoryError("Out of stack space.")`. Each dispatch now gets its own frame. The GEMM shape sweep found it on
  MoltenVK.

## Behaviour changes to check

- **`GemmF16.create(device)` compiles every algorithm** the device runs (three on Vulkan, four on native Metal) and
  picks one per shape by estimated time.
  - **Which algorithms run:** small and decode shapes now run SMALL or SKINNY on every backend, and the matrix
    kernel is chosen by the new costs.
  - **Results:** they stay within the same contract, and each algorithm is bit for bit its own reference.
  - **SKINNY's order differs:** its sum is in a different order from `reference`'s, so compare against
    `contract(...)` or the reference of `algorithm(shape)`.
  - **For `reference`'s bits on every shape:** use reproducible mode or `create(device, Algorithm.TILED, output)`.
  - **`AttentionF16`:** its products use the same dispatch.
- **`GemmF16.Shape` gains a `transposeA` component.** The 13- and 8-argument constructors remain.
- **The GEMM kernels' ABI:**
  - **Parameter block:** 17 fields, 68 bytes.
  - **Buffers:** bias, gate and residual are bound at 3, 4 and 5 (a placeholder when unused).
  - **Metal:** the matrix kernel takes its parameters at 6.
  - **Bundle version:** the matrix kernel's bundle is version 3.
- **Contract names** include the input type, for example "GemmF16 TILED, FP16 A and B, FP32 C".

## Install and consume

All public artifacts use version `1.8.0` under `org.dynamisengine`:

- `dynamis-gpu-api`
- `dynamis-gpu-metal`
- `dynamis-gpu-vulkan`
- `dynamis-gpu-primitives`
- `dynamis-gpu-vectrix`: it depends on `org.dynamisengine:vectrix:3.3.0`, which is distributed through the
  [Vectrix GitHub release](https://github.com/ljramones/vectrix/releases/tag/v3.3.0), not Maven Central.
- `dynamis-gpu-shaders`
- `dynamis-gpu-test` (optional testing helper)
- `dynamisgpu-parent` (parent POM)

The external `dynamis-parent` stays at `1.0.1`.

```sh
gh release download v1.8.0 --repo ljramones/DynamicGPU \
  --pattern 'dynamisgpu-1.8.0-maven.zip' --pattern SHA256SUMS
shasum -a 256 dynamisgpu-1.8.0-maven.zip
unzip dynamisgpu-1.8.0-maven.zip
sh dynamisgpu-1.8.0/install.sh
```

Compare the ZIP digest against `SHA256SUMS` before installation. Existing 1.7.x artifacts are unchanged. The
class-path JVM flag remains `--enable-native-access=ALL-UNNAMED`.

## Verification and platform scope

Before release:
- **Portable build:** passes (TESTS_PORTABLE tests; the hardware-only tests are skipped).
- **Hardware suites:** they pass on every target. Opt-in benchmarks are not counted.

  | Target | Driver | Compute conformance | Primitives (GEMM, softmax, attention, kit) |
  |---|---|---|---|
  | native Metal | Apple M4 Max, macOS 27.0.1 | TESTS_METAL_COMPUTE | TESTS_METAL_PRIM |
  | MoltenVK | 1.4.1 on the same machine, shared and dedicated transfer families | TESTS_MVK_COMPUTE | TESTS_MVK_PRIM |
  | Mesa lavapipe | llvmpipe, LLVM 20.1.2, Vulkan 1.4.318: Linux x86_64 in CI, Linux arm64 in a local container | TESTS_LVP_COMPUTE | TESTS_LVP_PRIM |

- **GEMM coverage:** every algorithm, for every input and output type, is checked on every target, with the
  epilogues and the grouped form.
  - **Bit for bit:** FP16 and BF16 everywhere, and FP32 inputs on native Metal and MoltenVK.
  - **Within the bound:** the matrix kernel, and FP32 inputs on lavapipe.
- **vectrix-gpu:** its 3,091 tests pass against this version on native Metal and MoltenVK.

Reproduce packaging without Central publication using `scripts/package-release.sh` with the Vulkan SDK configuration
from the [runtime guide](../compute-runtime.md). The included bridge (ABI 6, unchanged) targets macOS 13.0 arm64.
The stricter runtime MSL behaviour requires macOS 15+. Offline metallib generation and loading remain unverified.
